# Wishlist and item detail (brief §6.3, ADR-0005, ADR-0007, ADR-0013, ADR-0018, ADR-0037, ADR-0038)

## Rules (`:core:domain` `wishlist/`)

- `wishlistOf(items, reflections, savings, now, zone)` groups active items by `stageOf` in `WISHLIST_STAGE_ORDER` (Ready, Needs reflection, Saving, Cooling off), leaves empty groups out and sorts each group by `coolingEndsAt`, then `addedAt`, then id. Ready items whose "Wait" `recheckAt` is still ahead (`isWaiting`) form a last group with `waiting = true` ("Looking again later", soonest re-check first) and carry `recheckOn` (ADR-0040). Funding comes from `savings` (`Savings.fundingOf`, `.claude/rules/pool.md`); each entry carries `savings` (`SavingsProgress`) for wants while fun money is set up.
- `daysLeft(item, now, zone)`: calendar dates until the end (ADR-0018), at least 1 until the end instant has passed, 0 once cooled off.
- `untilWishlistChanges(items, now, zone)`: time to the next cooling-off end, re-check date or midnight, whichever is first. Detail and the decision screen use it with their one item.
- `itemDetailOf(item, reflection, savings, now, zone)`: stage, days left, `wantedForDays` (calendar days since `addedAt`), `reflected`, `linkProminent` / `imageProminent` = cooled off, `recheckOn` while waiting after "Wait", `savings` (null for needs) and `funMoneySetUp`. While cooling off the link is only in the overflow menu and the photo a small thumbnail (ADR-0013).
- `webLink(link)`: what "Open link" opens. `http`/`https` as is, no scheme → `https://`, any other scheme (`intent:`, `file:`, `javascript:`) → null: copy only.
- Edit reuses quick add's `CaptureForm` and `checkCapture`. `editFormOf(item, locale)` prefills the **exact** price (`formatForInput`). `editedItem(item, form, policy, locale, at, zone, imageRef)` keeps the given photo (default: the stored one) and applies the price first (`coolingEndAfterPriceEdit`: only extends), then the kind (`changeKind`). `waitChange(current, edited, now)` is what the form says under the price: `Extended`, `Starts` (need → want) or `None`.

## Screens and view models (`:app` `feature/wishlist/`)

- `WishlistViewModel` and `ItemDetailViewModel` recompute on the clock, not only on database changes: after each `untilWishlistChanges` they read `clock.instant()` again. Test time with `MutableClock` + `advanceTimeBy`.
- `groups == null` / `detail == null` means "not loaded yet": show nothing, never the empty state. An item ended or deleted meanwhile is `gone` on detail and edit.
- Each screen has a stateless `…Content` used for screenshots. Row: a 40 dp thumbnail only if there's a photo (decorative for screen readers), name, price, stage chip ("Waiting" while waiting), countdown / "Cooling-off over" / "Ready to decide" / "Look again on …"; tapping opens detail.
- Detail order: header (name, price, stage, countdown, "Wanted for N days", need line) → **reasons** (answers given so far, then a prompt card while the required ones are missing) → details → "Decide" (Ready or need, not waiting) / "Decide now" (`onDecide`, `.claude/rules/decision.md`) → actions. "Open link" as a text button only once cooled off; copy/open always in the overflow menu. "Mark as need" asks first, and says that what was set aside goes back (`MarkAsNeedBody`; edit asks the same on Save when its switch would do that, `confirmRelease`). For a want, a "Set aside" section after the photo (ADR-0046): `SavingsProgressBar` and equal "Set aside" / "Take back" buttons opening a `ModalBottomSheet` with `SavingsSheetContent` (amount, "Not yet set aside: …" / "Set aside for it: …", chips 50 € / 100 € (each fills in its amount) / "The rest" or "All", all from the domain (`quickAmounts`, `restToSetAside`, `checkAmount`); "Set aside" disabled once the price is covered or nothing is left (`canSetAside`); a refusal or a currency mismatch says "changed meanwhile" and writes nothing, Cancel and confirm as a `ButtonPair`); without fun money a line and "Set up fun money" (`onOpenFunMoney`). The sheet's state is `ItemDetailViewModel` (`SavingsActions`); `confirmSavings` reads the editor, not `uiState`, and the repository checks the limit again. Rows show "950 € to go" while Saving and a thin progress bar once something is set aside. The photo comes after the reasons: a 48 dp thumbnail + "Tap to view" while cooling off, a 200 dp cropped band once cooled off; a tap opens the whole photo full screen. The prompt card ("Start"/"Continue") and, once reflected, "Edit answers" open the reflection flow (`onReflect`, `.claude/rules/reflection.md`); a need without answers shows only a quiet "Add your reasons" text button, no section or card.
- Per-item view models get the id via assisted injection (`hiltViewModel<VM, VM.Factory> { it.create(id) }`); every navigation entry has its own ViewModel store (ADR-0037). Writes go through `ItemRepository.update(current, edited)` (compare-and-set): on `false` say the item changed meanwhile, never retry silently.
- Photos: view models map `imageRef` to a file with `ItemImageStore.fileFor` (no disk access); `ItemPhoto` decodes off the main thread via `PhotoCache` (sizes `THUMBNAIL_SIZE_PX`, `MAX_IMAGE_SIZE_PX`). Edit picks with `PickVisualMedia` (no permission) and imports at once; the item only changes on Save, and Save waits while a pick is importing. An unreadable pick keeps the previous photo and says so.
- Edit: fields from `feature/capture/ItemFields.kt` (shared with quick add), all shown. Save closes the screen; back discards. The form is filled once from the first load; later item changes don't overwrite typing, and saving applies the form to the newest item.
- Quick add is hosted once, in `AppNavigation`, outside the entries: `saved` events reach one collector and two entries can compose during a transition. Screens get `onAdd` and the shared `SnackbarHostState`.
